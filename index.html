003 Protocol p. 03

Three moves.
Nothing kept.

NullNode speaks exactly one dialect: the browser's own WebRTC. There is no media server to trust because there is no media server.

The one piece of infrastructure →

01 create

A key, not an account.

Your browser generates a six-character room key — 326 combinations. Nothing is registered anywhere. The key is only an address the relay will answer for the next two connections.

relay seesthe key
02 handshake

Two browsers find each other.

Session descriptions and ICE candidates travel as opaque text — a few kilobytes, held in memory for seconds. Then the peers negotiate DTLS-SRTP directly. The relay's job is over before you speak.

media pathpeer → peer
03 burn

The key stops existing.

Hanging up closes the peer connection, stops every track and deletes the room key from relay memory. There is no archive to leak, subpoena or sell — the conversation only ever existed on two devices.

006 Questions p. 06

Fair
questions.

The short version: it is as private as a phone call between two people and no more. Here is what that means in practice.

01Is the call actually encrypted?
Yes, and it is not optional. WebRTC mandates DTLS-SRTP, so a browser will refuse to send media unencrypted. NullNode also surfaces both certificate fingerprints in the room footer: read them out loud with the other person to rule out a man in the middle, exactly like verifying a key.
02Do I need to install anything?
No. A modern browser with camera and microphone permission is the entire requirement — Chrome, Edge, Firefox or Safari, desktop or mobile. Cameras are requested only when you press create or join, never on page load.
03Will it work behind my company network or CGNAT?
Usually, but not always. WebRTC needs a viable network path: public STUN gets most people through. If both sides sit behind symmetric NAT or a restrictive firewall, you need your own TURN server. NullNode ships with STUN only, by design — a public TURN would become a media relay and break the privacy claim. The airgap handshake often helps on locked-down networks, but it cannot create a path that does not exist.
04What happens if the relay is offline?
Switch to airgap mode. Two people copy one long session descriptor to each other through any channel they already trust — a message, an email, a carrier pigeon — paste it back, and the peer connection forms with no signalling server at all. Slower, uglier, completely serverless.
05Who can join my room?
Anyone holding the six-character key while the room is open. That is the whole point and also the whole risk: send the key over a channel you trust and hang up when you are done. Rooms hold two peers, reject a third, and expire on their own.
06Is it open source? Can I self-host it?
Both. The client is a static pair of pages — index.html for the story, app.html for the room — with plain CSS and ES5-style modules in /assets, served by GitHub Pages. The signalling relay is one Cloudflare Worker with a single Durable Object. Fork it, change the type, deploy under your own domain. MIT licensed, no build step, no bundler, no dependencies at runtime except the CDN assets listed above.
07How large a file can I send, and where does it go?
Sixty-four megabytes per file, chunked into sixteen-kilobyte frames and pushed straight down the data channel with backpressure so a slow link slows the sender instead of flooding it. The bytes never touch a server, a disk or a CDN: they go from your memory to theirs. Both of you have to be in the room — there is nothing to download later.
08Does the board survive a reload?
No, and that is deliberate. Strokes live in memory and are mirrored to the other screen as vectors, so the board stays crisp at any size. Close the tab and it is gone; export a PNG first if you want a copy. When a peer joins late, the existing strokes are replayed to them in one message.
09Why call it NullNode?
A node in a network is a place where data stops and is kept. NullNode is the opposite: a node that holds nothing, remembers nothing, and disappears when the conversation ends. The name is the design brief.
